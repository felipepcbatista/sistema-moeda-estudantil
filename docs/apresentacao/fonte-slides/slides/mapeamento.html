Das classes para as tabelas

ClasseMapeamento JPAPor quê
Usuario e subclassesHerança JOINEDLogin único entre os perfis; perfis com colunas bem diferentes
Transacao e subclassesHerança SINGLE_TABLECada subclasse soma um campo; o extrato lê uma tabela, sem joins
Endereco@EmbeddableObjeto de valor: vira colunas da tabela aluno
Conta@OneToOne com cascadeComposição: nasce e morre com o dono
Vantagem@OneToMany na empresaDesativada, não excluída: preserva o histórico de resgates

Fonte: pacote model do back-end e README, seção 8 · 9/18

Como o diagrama de classes virou tabelas. As duas heranças usam estratégias diferentes de propósito. Usuario usa JOINED: uma tabela-mãe com o login e uma tabela por perfil. Isso garante login único entre os três perfis com uma só restrição UNIQUE e evita colunas vazias. Transacao usa SINGLE_TABLE: uma tabela só, com uma coluna tipo, porque cada subclasse acrescenta um único campo e o extrato precisa ler tudo de uma vez. Endereço é objeto de valor, e Conta é composição. Vantagem é desativada em vez de excluída, para que os cupons já emitidos continuem apontando para ela.
