Tutorial · Spring Security + JWT

Cada um só mexe no que é seu

1. Login emite o token

{ "sub": "4",
"perfil": "ALUNO",
"exp": +8h }

Assinado com HS256. O front manda em toda chamada: Authorization: Bearer …

2. A rota declara quem pode

@PreAuthorize(
"hasRole('ALUNO') and
@acesso.ehOProprio(#id)")

Sem token ou token inválido: 401. Dado de outro usuário: 403.

Fonte: SegurancaConfig, TokenService, Acesso e SegurancaTest (README, seção 12) · 15/18

A principal entrega da S03 é a versão final dos CRUDs com segurança de verdade. Antes, a tela escondia os botões, mas a API aceitava qualquer chamada. Agora, no login, a API emite um token JWT assinado, com o id do usuário, o perfil e a validade de 8 horas. O front envia esse token em toda requisição. O Spring Security valida a assinatura, e cada rota declara quem pode usá-la com PreAuthorize. O componente Acesso responde se o id da rota é do usuário logado. Testamos com tokens reais: a aluna Maria recebe 403 ao tentar ler o cadastro do João, e um professor recebe 403 ao tentar gastar o saldo de outro professor.
