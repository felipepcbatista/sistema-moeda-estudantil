Arquitetura

MVC em três camadas e um banco

View

React + Vite

Painéis por perfil, sessão com o token e Axios para chamar a API

Controller

REST Spring

Recebe o JSON, valida o DTO e confere quem pode acessar

Model

Service + JPA

Regras de negócio, entidades e repositories

Dados

PostgreSQL

Schema versionado pelo Flyway

Regra que seguimos: o controller não decide nada de negócio. Saldo, motivo obrigatório e código do cupom ficam no service, e a regra de posse fica na anotação de segurança.

Fonte: diagrama de componentes (docs/diagramas) e README, seção 7 · 4/18

O enunciado exige MVC. A View é o front-end em React. O Controller são os controllers REST do Spring, que só traduzem HTTP: recebem o JSON, validam o formato e conferem a permissão. O Model concentra as regras: os services, as entidades JPA e os repositories. Ponto para enfatizar: nenhuma regra de negócio mora no controller. Se amanhã trocarmos a tela, as regras continuam valendo, porque estão no service e na API.
